# المثال الرابع — PostgreSQL في حاوية، وحفظ البيانات بمساحات التخزين

لا يوجد كود في هذا المثال، فقط أوامر.
نشغّل قاعدة بيانات PostgreSQL من الصورة الرسمية، ثم نحل مشكلة ضياع البيانات.

## 1) تشغيل PostgreSQL في حاوية

```bash
docker run --rm -d --name postgres-test -e POSTGRES_PASSWORD=password postgres
```

| الخيار | معناه |
|---|---|
| `--rm` | احذف الحاوية تلقائياً عند إيقافها |
| `-d` | شغّل الحاوية في الخلفية وأعد لي الطرفية فوراً |
| `--name postgres-test` | اسم ثابت للحاوية بدل اسم عشوائي، حتى نستخدمه في الأوامر التالية |
| `-e POSTGRES_PASSWORD=password` | متغيّر بيئة تقرأه الصورة لتعيين كلمة مرور المستخدم postgres |

لماذا `-d`؟
خادم قاعدة البيانات برنامج يعمل باستمرار ولا ينتهي.
بدون `-d` تبقى الطرفية مشغولة بسجلات الخادم، ولا نستطيع كتابة أوامر أخرى.
مع `-d` يعمل الخادم في الخلفية، ونعود للطرفية لنتصل به.

## 2) الدخول إلى قاعدة البيانات

```bash
docker exec -it postgres-test psql -U postgres
```

- `docker exec`: نفّذ أمراً داخل حاوية تعمل الآن.
- `-it`: جلسة تفاعلية نكتب فيها ونقرأ الرد.
- `psql -U postgres`: الأمر الذي ننفّذه داخل الحاوية، وهو برنامج psql بالمستخدم postgres.

بعدها نكتب أوامر SQL بشكل عادي، كأن القاعدة مثبتة على الجهاز.

## 3) ربط المنفذ للاتصال من خارج الحاوية

```bash
docker run --rm -d --name postgres-test -e POSTGRES_PASSWORD=password -p 5444:5432 postgres
```

PostgreSQL يستمع داخل الحاوية على المنفذ 5432.
الخيار `-p 5444:5432` يقول: ما يصل إلى المنفذ 5444 على جهازي، حوّله إلى المنفذ 5432 داخل الحاوية.

الآن أستطيع الاتصال بالقاعدة من برنامج إدارة قواعد البيانات على جهازي بهذه البيانات:

```text
Host:     localhost
Port:     5444
User:     postgres
Password: password
```

اخترت 5444 وليس 5432 لأن عندي PostgreSQL مثبتاً على الجهاز ويستخدم 5432.
لو استخدمت الرقم نفسه لتعارض المنفذان، ولظهر خطأ أن المنفذ مستخدم.

## 4) المشكلة: البيانات تضيع

أنشأت جدولاً وأضفت بيانات، ثم أوقفت الحاوية.
بسبب `--rm` حُذفت الحاوية، وعند التشغيل من جديد كانت القاعدة فارغة:

```text
ERROR:  relation "notes" does not exist
```

السبب: الحاوية لها طبقة كتابة خاصة بها، وكل ما يُكتب داخلها يعيش ما دامت الحاوية موجودة.
عند حذف الحاوية تُحذف طبقة الكتابة ومعها البيانات.

## 5) الحل: مساحة تخزين

مساحة التخزين مجلد يديره Docker خارج الحاوية.
تُربط بمسار داخل الحاوية، فما يُكتب في هذا المسار يُحفظ فيها.
حذف الحاوية لا يحذف مساحة التخزين.

إنشاء مساحة التخزين:

```bash
docker volume create postgres-test
```

عرض مساحات التخزين:

```bash
docker volume ls
```

```text
DRIVER    VOLUME NAME
local     4164773ead1372ebf1b17fa4d2f9b08313714b20572f8cea880127a81d4e3020
local     portainer_data
local     postgres-test
```

السطر ذو الاسم الطويل مساحة تخزين **مجهولة**.
صورة PostgreSQL تطلب مساحة تخزين لمجلد البيانات دائماً.
إذا لم نحدد واحدة بالخيار `-v`، ينشئ Docker واحدة باسم عشوائي.
مع `--rm` تُحذف المجهولة مع الحاوية، لذلك لم تحفظ بياناتنا في الخطوة الرابعة.

## 6) التشغيل مع مساحة التخزين

```bash
docker run --rm -d --name postgres-test -e POSTGRES_PASSWORD=password -p 5444:5432 -v postgres-test:/var/lib/postgresql postgres
```

- `-v postgres-test:/var/lib/postgresql`: الاسم قبل النقطتين مساحة التخزين، وبعدهما المسار داخل الحاوية.

جرّبت ذلك فعلياً: أنشأت جدولاً، أوقفت الحاوية فحُذفت، ثم شغّلت حاوية جديدة بالأمر نفسه:

```text
postgres=# SELECT * FROM notes;
 id |        body
----+---------------------
  1 | hello from a volume
(1 row)
```

البيانات ما زالت موجودة، لأنها محفوظة في مساحة التخزين وليس في الحاوية.

### تنبيه مهم عن مسار البيانات

المسار الصحيح يعتمد على إصدار PostgreSQL:

| الإصدار | المسار الذي نربطه |
|---|---|
| الثامن عشر وما بعده | `/var/lib/postgresql` |
| السابع عشر وما قبله | `/var/lib/postgresql/data` |

الوسم `latest` يعني الآن الإصدار 18، لذلك المسار في هذا المثال صحيح.
لكن لو تغيّر إصدار `latest` في المستقبل، قد يتغيّر المسار وتظهر القاعدة فارغة.
هذا سبب إضافي لتثبيت رقم الإصدار، مثل `postgres:18`.

## 7) أين تُحفظ البيانات فعلياً على الجهاز؟

```bash
docker volume inspect postgres-test
```

يظهر في الناتج الحقل `Mountpoint`، مثل:

```text
/var/lib/docker/volumes/postgres-test/_data
```

لا تعدّل الملفات هناك يدوياً. Docker هو من يدير هذا المجلد.

## ملخص

| الحالة | ماذا يحدث للبيانات عند حذف الحاوية؟ |
|---|---|
| بلا مساحة تخزين | تُحذف |
| مساحة تخزين مسمّاة بالخيار `-v` | تبقى |

لحذف مساحة التخزين نفسها عندما لا تحتاجها:

```bash
docker volume rm postgres-test
```
