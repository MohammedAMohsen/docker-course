# المثال الثالث — تطبيق React مع بناء متعدد المراحل

تطبيق مهام بسيط مبني بـ React و Vite، نبنيه داخل Docker ثم نقدّمه عبر خادم Nginx.

![تطبيق React داخل حاوية Nginx](../screenshots/example-3-react.png)

## الفكرة الأساسية

تطبيق React يمر بمرحلتين:

1. **البناء:** نحتاج Node و npm لتحويل الكود إلى ملفات HTML و CSS و JavaScript جاهزة.
2. **التقديم:** نحتاج فقط خادم ويب يرسل هذه الملفات إلى المتصفح.

بعد البناء لا نحتاج Node أبداً.
لذلك نستخدم **البناء متعدد المراحل**: مرحلة بصورة Node للبناء، ومرحلة بصورة Nginx للتشغيل.
الصورة النهائية تأخذ المرحلة الأخيرة فقط.

## الفرق في الحجم (أرقام حقيقية من جهازي)

```text
node:latest        1.8GB    صورة البناء
react-app:latest   102MB    الصورة النهائية
```

الصورة النهائية أصغر بحوالي ثماني عشرة مرة، لأن Node ومكتباته بقيت في المرحلة الأولى.

## أهم التعليمات الجديدة

| التعليمة | معناها |
|---|---|
| `FROM node:latest AS builder` | بداية مرحلة وتسميتها |
| `COPY --from=builder ...` | النسخ من مرحلة سابقة بدل النسخ من الجهاز |
| `EXPOSE 80` | توثيق للمنفذ الذي يستمع عليه التطبيق |

`EXPOSE` لا يفتح أي منفذ على الجهاز.
الذي يربط منفذ الجهاز بمنفذ الحاوية هو الخيار `-p` عند التشغيل.

## التشغيل

```bash
cd example-3-react-multistage
```

```bash
docker build -t react-app:latest .
```

```bash
docker run -it --rm -p 3001:80 react-app:latest
```

افتح المتصفح على: `http://localhost:3001`

- `-p 3001:80`: منفذ الجهاز 3001 يُحوَّل إلى المنفذ 80 داخل الحاوية حيث يعمل Nginx.

## التشغيل بدون Docker (للتطوير)

```bash
npm install
```

```bash
npm run dev
```

ثم افتح العنوان الذي يظهر في الطرفية، وغالباً يكون `http://localhost:5173`.

## ملاحظات

- لا يوجد ملف `package-lock.json` هنا، لذلك استخدمنا `npm install`.
  في المثال السادس يوجد الملف، فاستخدمنا `npm ci` لأنه يثبّت الإصدارات المسجّلة فيه بالضبط.
- بيانات المهام مؤقتة داخل المتصفح، ولا توجد قاعدة بيانات في هذا المثال.
