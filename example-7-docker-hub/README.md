# المثال السابع — رفع الصور إلى Docker Hub وتشغيل المشروع منها

في المثال السادس بنينا الصور على جهازي من الكود.
هنا نرفع هذه الصور إلى **Docker Hub**، ثم نشغّل المشروع كاملاً منها **بدون الكود**.
هكذا يُنقل المشروع إلى أي جهاز أو خادم: ملف Compose وملفّا متغيّرات فقط.

## ما هو Docker Hub؟

مستودع على الإنترنت لحفظ الصور ومشاركتها، مثل GitHub لكن للصور بدل الكود.
الصور الرسمية التي استخدمناها مثل `postgres` و `nginx` و `python` تأتي منه.

صوري المرفوعة (عامة):

- `mohammed7845/workboard-backend`
- `mohammed7845/workboard-frontend`

## الجزء الأول: رفع الصور

### 1) تسجيل الدخول

```bash
docker login
```

### 2) وسم الصور المحلية باسم المستودع

اسم الصورة على Docker Hub يجب أن يبدأ باسم المستخدم:

```text
اسم-المستخدم/اسم-المستودع:الوسم
```

الصور المحلية من المثال السادس اسمها `workboard-backend` و `workboard-frontend`.
نعطيها أسماء جديدة تبدأ باسم المستخدم:

```bash
docker tag workboard-backend:latest mohammed7845/workboard-backend:latest
```

```bash
docker tag workboard-frontend:latest mohammed7845/workboard-frontend:latest
```

الأمر `tag` لا ينسخ الصورة ولا يغيّرها.
هو يضيف اسماً ثانياً يشير إلى الصورة نفسها، لذلك يظهر الاسمان في القائمة بالحجم نفسه.

### 3) رفع الصور

```bash
docker push mohammed7845/workboard-backend:latest
```

```bash
docker push mohammed7845/workboard-frontend:latest
```

إذا لم يكن المستودع موجوداً على Docker Hub، يُنشأ تلقائياً عند أول رفع.

## الجزء الثاني: التشغيل من الصور

في هذا المجلد ثلاثة ملفات فقط مهمة: `compose.yaml` وملفّا المتغيّرات.

### 1) تجهيز ملفات المتغيّرات

```bash
cp .env.example .env
```

```bash
cp backend.env.example backend.env
```

| الملف | من يقرؤه | ما فيه |
|---|---|---|
| `.env` | أداة Compose نفسها، لتعويض `${...}` في الملف | بيانات القاعدة |
| `backend.env` | حاويتا `migrate` و `backend` | إعدادات Django |

الفرق مهم: ملف `.env` بجانب ملف Compose يُقرأ تلقائياً ولا يدخل أي حاوية بنفسه.
أما الملف المذكور في `env_file` فمحتواه يدخل الحاوية كمتغيّرات بيئة.

### 2) سحب الصور

```bash
docker compose pull
```

### 3) التأكد من صحة الملف

```bash
docker compose config
```

يعرض الملف بعد تعويض المتغيّرات. إذا نسيت ملف `.env` ستظهر قيم فارغة وتحذيرات.

### 4) التشغيل

```bash
docker compose up -d
```

افتح المتصفح على: `http://localhost:3001`

### 5) الحالة والسجلات

```bash
docker compose ps -a
```

```bash
docker compose logs -f
```

### 6) الإيقاف

```bash
docker compose down
```

## ما الذي تعلّمته من هذا المثال

- الصورة هي ما ننقله، وليس الكود.
- لا أسرار داخل الصور ولا داخل ملف Compose. الأسرار في ملفات متغيّرات لا تُرفع إلى GitHub.
- القاعدة هنا بلا `ports`، فلا يصل إليها أحد من خارج شبكة المشروع. هذا أكثر أماناً.

## ملاحظات وجدتها عند المراجعة

**1) لوحة الإدارة بلا تنسيق.**
هنا `DJANGO_DEBUG=0`، وخادم التطوير `runserver` لا يقدّم ملفات التنسيق عندما يكون وضع التطوير متوقفاً.
جرّبت ذلك فعلياً، فرجع طلب ملف التنسيق بالرمز 404:

```text
"GET /static/admin/css/base.css HTTP/1.1" 404 179
```

الحل الصحيح للإنتاج مذكور في قسم الدروس المستفادة في README الرئيسي.

**2) الصور المرفوعة أقدم من إصلاح nginx.conf.**
إصلاح تسجيل الدخول إلى لوحة الإدارة في المثال السادس تمّ بعد رفع الصور.
لتصل الصور المرفوعة إلى النسخة المصلحة: ابنِ المثال السادس من جديد، ثم كرّر خطوتي الوسم والرفع.
