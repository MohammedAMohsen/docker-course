# المثال الثاني — مشروع Django حقيقي داخل حاوية

مدوّنة Django كاملة (منشورات، تسجيل مستخدمين، صور شخصية، استعادة كلمة المرور).
كتبتها سابقاً بدون Docker، وهنا نضعها داخل حاوية.

## ما الجديد مقارنة بالمثال الأول؟

1. تثبيت مكتبات من ملف `requirements.txt`.
2. ترتيب التعليمات للاستفادة من ذاكرة البناء المؤقتة.
3. ملف `.dockerignore` لإبعاد ملفات لا نريدها في الصورة.
4. تمرير الأسرار عند التشغيل، وليس وضعها داخل الصورة.
5. ربط منفذ الحاوية بمنفذ الجهاز حتى يصل المتصفح إلى التطبيق.

## ذاكرة البناء المؤقتة

كل تعليمة في `Dockerfile` تصنع طبقة، ويحفظ Docker هذه الطبقات.
عند إعادة البناء، يعيد استخدام كل طبقة لم تتغيّر ملفاتها.
عند أول طبقة تغيّرت، يعيد بناءها وكل ما بعدها.

لذلك ننسخ `requirements.txt` وحده أولاً ونثبّت المكتبات، ثم ننسخ الكود:

```dockerfile
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
```

عند تعديل الكود فقط، يتخطى Docker خطوة التثبيت. تظهر في سجل البناء كلمة `CACHED`.

## ملف .dockerignore

يعمل مثل `.gitignore` لكن لعملية البناء.
أهم سطر فيه هو `.env`: ملف الأسرار لا يدخل الصورة.
لو دخل الصورة، فكل من يحصل على الصورة يستطيع قراءة الأسرار منها.

## ملف المتغيّرات

```bash
cp .env.example .env
```

ثم عدّل القيم داخل `.env`.

## التشغيل

```bash
cd example-2-django-blog
```

```bash
docker build -t django-app:latest .
```

```bash
docker run --rm --env-file .env -p 8000:8000 django-app
```

افتح المتصفح على: `http://localhost:8000`

### نسخة نظيفة بلا قاعدة بيانات

ملف قاعدة البيانات `db.sqlite3` غير مرفوع إلى المستودع.
لذلك في نسخة جديدة نشغّل الترحيلات أولاً ثم الخادم، في أمر واحد:

```bash
docker run --rm --env-file .env -p 8000:8000 django-app sh -c "python manage.py migrate && python manage.py runserver 0.0.0.0:8000"
```

## شرح خيارات التشغيل

- `--env-file .env`: يقرأ المتغيّرات من الملف ويضعها داخل الحاوية عند التشغيل.
- `-p 8000:8000`: الرقم الأول منفذ الجهاز، والثاني منفذ الحاوية.
  المعنى: ما يصل إلى منفذ الجهاز 8000 يُحوَّل إلى منفذ الحاوية 8000.
- `0.0.0.0:8000` في أمر التشغيل: الخادم يستقبل من خارج الحاوية.
  لو استمع على `127.0.0.1` فقط، فلن يصله المتصفح حتى مع وجود `-p`.

## مشكلة سيحلّها المثال الرابع

قاعدة البيانات هنا ملف داخل الحاوية.
مع الخيار `--rm` تُحذف الحاوية عند إيقافها، ومعها كل منشور أو مستخدم أضفته.
حل هذه المشكلة هو مساحات التخزين، وهي موضوع المثال الرابع.

## ملاحظات

- الملف `blog/views_old.py` ملاحظاتي عن الطريقة القديمة بالدوال قبل التحويل إلى الأصناف. ليس جزءاً من التشغيل.
- صور المستخدمين الشخصية وملف قاعدة البيانات غير مرفوعة إلى المستودع لأنها بيانات خاصة.
