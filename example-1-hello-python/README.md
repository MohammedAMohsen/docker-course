# المثال الأول — أول صورة Docker

أبسط مثال ممكن: ملف Python يطبع جملة واحدة، نضعه داخل صورة ونشغّله في حاوية.

## الملفات

| الملف | الوظيفة |
|---|---|
| `index.py` | يطبع جملة واحدة |
| `Dockerfile` | وصفة بناء الصورة |

## المفاهيم في هذا المثال

**الصورة:** قالب جاهز للقراءة فقط، فيه نظام صغير وبرنامجك ومكتباته.
تُبنى مرة واحدة من ملف `Dockerfile`.

**الحاوية:** نسخة تعمل من الصورة.
يمكن تشغيل عدة حاويات من الصورة نفسها، تماماً كما تفتح عدة نوافذ من البرنامج نفسه.

**ملف Dockerfile:** قائمة تعليمات تُنفَّذ من الأعلى إلى الأسفل لبناء الصورة.

| التعليمة | معناها |
|---|---|
| `FROM` | الصورة الأساسية التي نبدأ منها |
| `WORKDIR` | مجلد العمل داخل الصورة |
| `COPY` | نسخ ملفات من الجهاز إلى الصورة |
| `CMD` | الأمر الافتراضي عند تشغيل الحاوية |

## التشغيل

```bash
cd example-1-hello-python
```

```bash
docker build -t hello-python:latest .
```

```bash
docker run --rm hello-python
```

الناتج:

```text
hello, from docker !!!
```

## شرح الأوامر

- `-t hello-python:latest`: اسم الصورة ووسمها. الاسم قبل النقطتين، والوسم بعدهما.
- النقطة في آخر أمر البناء: مجلد البناء. يرسل Docker محتوى هذا المجلد إلى محرّك البناء.
- `--rm`: احذف الحاوية تلقائياً بعد أن تتوقف، حتى لا تتراكم حاويات منتهية.

## ملاحظة: حجم الصورة

```bash
docker image ls hello-python
```

```text
REPOSITORY     TAG       SIZE
hello-python   latest    1.63GB
```

الحجم كبير جداً لبرنامج من سطر واحد.
السبب أن الصورة `python:latest` تحتوي نظاماً كاملاً بأدوات كثيرة لا نحتاجها.
الحل في المشاريع الحقيقية: صورة مصغّرة بإصدار ثابت مثل `python:3.13-slim`.
التفاصيل في قسم الدروس المستفادة في ملف README الرئيسي.
